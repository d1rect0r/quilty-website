## Context

Search is a high-retrofit-cost seam. The call surface proliferates across the marketing site (Cmd-K modal, search results page, in-page filters) and eventually into the portal (settings search, account-data search). Without a locked port, every feature ships its own search call signature; every vendor swap touches every call site.

Quilty is a vaping cessation product — NOT a mental-health support service. The original D.1 plan considered crisis-keyword pinning above search results (mental-health-aligned safety canon used by Lyra / Talkspace / Cerebral); the product clarification dropped this UX from D.1 scope. Future relapse-prevention surfacing (NRT lines, 1-800-QUIT-NOW) is a separate UX track that lives at the page-component layer and does not impact the port shape.

Pre-launch traffic is zero; pre-launch content is also near-zero (zero MDX content at M1.6). A hosted search engine (Algolia / Typesense / Meilisearch) would cost $99-$300/month minimum with zero benefit at this scale. Pagefind ships a static client-side index at build time with $0 hosted cost AND the strongest privacy stance available (zero queries leave the device).

The "do nothing" outcome: every feature reaches for either a hand-rolled regex search OR a hosted engine without a uniform port. Vendor swap becomes a multi-call-site refactor; query privacy degrades silently when consumers reach for whatever's convenient.

## Decision

We will ship a new workspace package `@quilty/search` with ONE typed `SearchIndex` port, ONE production adapter (`makePagefindAdapter()`), ONE in-memory fake (`makeInMemorySearchIndex()`, exposed via `@quilty/search/testing`), AND ONE swap-target skeleton (`makeAlgoliaAdapter()` — throws at instantiation until the activation trigger).

### Decision A — Port shape (LCD across 4 engines)

```ts
interface SearchIndex {
  readonly search: (q: string, opts?: SearchOptions) => Promise<SearchResponse>;
}

interface SearchOptions {
  readonly filters?: ReadonlyArray<SearchFilter>;
  readonly sort?: SearchSort;
  readonly page?: number;
  readonly pageSize?: number;
  readonly signal?: AbortSignal;
}

interface SearchResponse {
  readonly hits: ReadonlyArray<SearchHit>;
  readonly total: number;
  readonly facets?: Readonly<Record<string, ReadonlyArray<FacetBucket>>>;
}
```

The port is the **lowest common denominator** of the public TS SDK surfaces for Pagefind, Algolia, Typesense, and Meilisearch — chosen so a future swap is a one-file adapter change.

`SearchHitCategory` is a **closed union** (`'blog' | 'customers' | 'legal' | 'changelog' | 'page'`). Adapters that consume vendor-specific category metadata MUST narrow to the closed set OR extend the union at the port layer (port-owned vocabulary per ADR-0014 Rule 4).

### Decision B — Pagefind as the default production adapter

- **Bundle:** `/pagefind/pagefind.js` (generated by `pnpm build:pagefind` post-`next build`); ~50 KB gzipped.
- **Index segments:** static `/pagefind/index/*.pf_index` files; browser fetches segments via HTTP range requests.
- **Privacy stance:** zero queries leave the device. The query string NEVER appears in a network request.
- **Lazy load:** the adapter dynamic-imports the bundle on first `search()` call so the initial page payload stays under the 60 KB per-route budget at all routes (ADR-0018).
- **Scale ceiling:** Pagefind handles ~1000 indexed pages with sub-100ms query times on commodity client hardware. Content-volume scaling is NOT the swap trigger.

### Decision C — Swap-target skeleton (Algolia)

`makeAlgoliaAdapter()` throws `AlgoliaAdapterNotActivatedError` at instantiation today. The skeleton ships so:

1. The composition-root TYPE surface stays vendor-swappable from day one.
2. The ESLint vendor-import allowlist gets the entry now (not later, scrambling at activation).
3. The activation PR is mechanically 4 lines: replace the skeleton body, install `algoliasearch`, wire composition.client.ts, add an ADR amendment.

This matches the `makeOpossumCircuitBreaker()` pattern from ADR-0017.

### Decision D — Swap activation triggers (NOT content volume)

Migration from Pagefind to a hosted engine happens when ANY of these fire — content volume alone does NOT trigger:

1. **Typo tolerance becomes a UX requirement** — Pagefind has none; Algolia/Typesense/Meilisearch all ship typo-tolerant scoring out of the box.
2. **Facet aggregations across 100+ distinct values** — Pagefind facets are exact-match only; hosted engines compute facet counts efficiently.
3. **Search analytics (query → click conversion telemetry)** — Pagefind has none; hosted engines emit telemetry events.

Each trigger is filed on the C.1 watchlist with the threshold and the canonical migration steps.

### Decision E — Privacy stance preservation on swap

ANY hosted-engine swap MUST preserve the zero-query-off-device guarantee via:

1. **First-party proxy** at `apps/web/app/api/search/route.ts`. The client NEVER holds the engine API key; the proxy strips client IP + forwards an opaque user-agent token (e.g., `X-Algolia-UserToken`).
2. **Per-query rate limit** + **per-tenant key isolation** at the proxy layer.
3. **BAA in force** with the vendor before activation (HIPAA-aligned posture; Algolia ships BAA on Enterprise tier; Typesense Cloud requires direct negotiation).

The proxy pattern is mandatory: a client-side hosted-engine SDK leaks per-query telemetry to the vendor even with `analytics: false`. The proxy makes the data-export boundary explicit.

### Decision F — Empty-query invariant

An empty query string (or whitespace-only) returns `{ hits: [], total: 0 }`. It does NOT match-everything. This is the canonical Pagefind behavior AND the documented Algolia/Typesense/Meilisearch behavior; the port locks it as an invariant so future adapter swaps don't accidentally widen the surface.

### Decision G — In-memory fake at `@quilty/search/testing`

The in-memory fake matches the production-adapter contract exactly: case-insensitive substring scoring against `title` + `excerpt`, equality filters, 1-indexed pagination, abort-signal honoring, score in [0, 1]. Contract tests parameterise against the fake AND every real adapter so the LCD shape holds across the entire matrix.

### Decision H — Flag-gated activation UX

At M1.6 the search route renders `<ComingSoonSearch>` (placeholder UI). The composition root wires `makeInMemorySearchIndex(...)` because Pagefind would have nothing to index. When MDX content lands at M3+:

1. `pnpm build:pagefind` populates the bundle.
2. Composition root flips to `makePagefindAdapter(...)`.
3. `features.flag('search_enabled')` flips to `true`.
4. `<ComingSoonSearch>` becomes `<SearchInterface>` via the existing flag-gated dynamic import.

The flag-gated `<ComingSoonSearch>` placeholder ships at M1.6 so the route shape (URL + a11y + metadata) is locked before content lands.

## Consequences

**Positive:**

- Vendor swap is a one-file adapter change. Every consumer holds the `SearchIndex` interface.
- Zero hosted cost at zero traffic. The Pagefind bundle is static; no runtime infrastructure to provision.
- Strongest privacy posture available: queries never leave the device. The hosted-engine activation contract makes the migration explicit (proxy + BAA).
- Closed-union `SearchHitCategory` keeps the consumer surface stable across vendor swaps; adapter authors are forced to either narrow to the known set or extend the union deliberately.
- The skeleton + closed-trigger activation gates prevent a "we'll just adopt Algolia later" drift; the typo-tolerance / facets / analytics threshold is explicit.

**Negative:**

- Pagefind requires a post-build step (`pnpm build:pagefind`). The build pipeline grows by one stage. Build time + 5-15s on a cold cache.
- No typo tolerance until the activation trigger fires. Users searching `quilty` find no hits when they typed `qulity`. Acceptable at the zero-content scale; flagged for the activation watchlist.
- The Pagefind bundle (~50 KB gzipped) lazy-loads on first search, BUT the dynamic-import code path adds ~2 KB to every route that wires the SearchInterface client island. Tolerated under the 60 KB per-route budget.
- The injection seam (`PagefindAdapterOptions.loadModule`) leaks a test-only abstraction into the production API surface. Mitigated by docstring + placement in the options block.

**Neutral:**

- Cmd-K modal UX is deferred to first MDX content + the keyboard-shortcut binding decision (D-shortcut family at M3+).
- Future `crisis-resources.ts` domain module ships empty at M1.6 (vaping-cessation relapse-prevention resources land at M3+ identity-discovery).

## Anti-patterns avoided

- **Hand-rolled regex search** — every search consumer would invent its own scoring + filtering shape. Locked by the SearchIndex port.
- **Direct hosted-engine SDK import in client code** — leaks the query string + IP to the vendor without a BAA. Locked by ESLint vendor-import allowlist + the first-party-proxy requirement.
- **Open-ended `category` string field** — adapters could emit arbitrary categories, drifting the consumer surface. Locked by the closed-union `SearchHitCategory`.
- **Match-everything on empty query** — Pagefind defaults to this; we override at the port layer because empty-query results blow out the rendered page.
