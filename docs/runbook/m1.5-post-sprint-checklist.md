## 1. HIPAA officer designation filing (D139)

**Owner**: founder. **Pre-launch blocking.**

File at `quilty-aws/docs/compliance/security_officer_designation.md`
(cross-repo; the website repo references this filing but the
document itself lives in the AWS infra repo because the
designation is a per-organization fact, not per-product). The
existing security-officer designation file in quilty-aws is the
load-bearing artefact; this checklist item EXTENDS that file with
the Privacy Officer (§164.530(a)) section + training attestation
(§164.308(a)(5)) + the COI mitigation block — additive edits to
the cross-repo file rather than a separate document.

Required content (HIPAA §164.530(a) + §164.308(a)(2) + post-
Cerebral enterprise canon):

- Founder formally designated as **Privacy Officer**
  (§164.530(a)) responsible for the development and implementation
  of privacy policies + procedures.
- Same founder formally designated as **Security Officer**
  (§164.308(a)(2)) responsible for the development and
  implementation of administrative, physical, and technical
  safeguards.
- Effective date of designation (typically the sprint close).
- Retention: 6 years per HIPAA §164.530(j).
- Successor-naming clause: if the founder steps down from either
  role, a successor must be named within 30 days; the designation
  document is itself an audit event. Post-incorporation
  (Delaware C-Corp formation milestone), successor naming
  requires board resolution rather than founder memo.
- **Training attestation** (§164.308(a)(5)): annual HIPAA training
  completion documented for the founder + any future direct
  reports. The HHS sample designations include this as a
  load-bearing audit field; without it, the OCR notification form
  has no proof the designated officer has completed required
  training.
- **Conflict-of-interest mitigation**: founder holds BOTH officer
  roles simultaneously. HIPAA §164.308(a)(2) permits this at
  small organisational scale, but the enterprise canon (Cerebral
  post-settlement, Talkspace 2024) recommends documenting the
  mitigation plan — typically external counsel review of policy
  changes that materially affect both privacy + security
  postures. Mitigation activates with the external counsel
  retainer (item 9).

Until this filing exists, the SEV1 + PHI escalation pipeline at
`docs/runbook/incidents/sev-taxonomy.md` cannot complete an OCR
§164.404 notification (the "covered entity's designated Privacy
Officer" line on the OCR breach-notification form has no name).

## 12. SEV1 + PHI audit-log export procedure

**Owner**: founder. **Pre-launch blocking** — required for
HIPAA §164.530(j) 6-year retention compliance.

Per the corrected `sev-taxonomy.md` discipline, Discord channel
messages MUST NOT be relied on as the §164.530(j) audit record.
Document the SEV1 audit-log export procedure:

1. After SEV1 closure, export the `#quilty-incidents` Discord
   thread.
   - **Primary tool:** DiscordChatExporter
     (https://github.com/Tyrrrz/DiscordChatExporter). Community-
     maintained CLI; downloads channel messages to a structured
     JSON / HTML archive.
   - **Fallback (if DiscordChatExporter breaks or becomes
     unavailable):** call the Discord REST API directly —
     `GET /channels/{channel_id}/messages?limit=100&before={cursor}`
     with pagination until the channel start is reached. Pipe
     the JSON stream to a local file. A skeleton script at
     `scripts/discord-export-bot.ts` (deferred until first SEV1
     fires) wraps the pagination + auth + retry logic.
   - Bot vs. CLI choice should not block the export; the
     procedural fallback exists for both.
2. Encrypt the export at-rest before upload (AES-256-GCM via
   `aws s3 cp` with the bucket's KMS key, OR equivalent
   client-side encryption if the export tool supports it).
3. Upload to the `quilty-aws/log-archive/` S3 bucket with
   Object Lock + 6-year lifecycle policy.
4. Author the SEV1 post-mortem per the
   `docs/runbook/incidents/README.md` template — within 5
   business days of SEV1 closure (HIPAA §164.312(c)(1) Security
   Incident Procedures expectation).
5. File the post-mortem at
   `docs/runbook/incidents/post-mortems/YYYYMMDD-{issue-slug}.md`
   with a cross-reference to the S3 audit-log export path. The
   in-repo post-mortem is the human-readable narrative; the S3
   export is the per-§164.530(j) compliance record.

The S3 bucket + Object Lock policy already exist in the
`quilty-aws/log-archive/compliance_events.tf` Terraform layer
(`COMPLIANCE` mode + 7-year retention, exceeds the 6-year
HIPAA floor).
