# Trigger Watchlist — Decision Activation Ledger

> **Owner:** founder (Volodymyr Petrychenko)
> **Review cadence:** Quarterly — sort by `last_reviewed` ascending; rows >90 days at top.
> **Escalation:** Add monthly lightweight check when first technical hire lands.
> **Schema (12 columns):** ID • Title • Category • Trigger Type (`metric` / `event` / `date` / `dependency`) • Trigger Condition • Status (`armed` / `pending` / `fired` / `closed`) • ADR/D-ref • Owner • Delegate • Target Date • Last Reviewed • Notes.

This runbook is the single source of truth for every "do this at trigger X" decision deferred during M1.x architecture lock-down. Every entry cross-references the ADR or D-number that originated the deferral.

The LAUNCH-scoped subset of these triggers (plus deployment-close-out items that never got TW rows) is indexed in [launch-gate.md](./launch-gate.md) — the one-page Wave-3 execution list.

---

## How to use this watchlist

1. **At review time** (quarterly): scan rows whose `Last Reviewed` is >90 days old; refresh `Status` + `Last Reviewed` for each. Promote `pending` to `armed` when the trigger predicate becomes externally observable; promote `armed` to `fired` when the trigger fires + work begins.
2. **When a trigger fires:** open the linked ADR/D-ref, follow its activation procedure, then mark this row `fired` (or `closed` if no follow-up).
3. **When adding a new deferral:** allocate the next `TW-NNN` ID; back-link from the originating ADR's _Activation triggers_ section.
