# Launch gate — the one-page index of everything between "deployment closed" and "public launch"

> **Purpose.** After the Wave-1 deployment close-out, the AWS platform is
> frozen except for scheduled activation batches. This page is the single
> index of every gate that must flip (or be consciously waived) before the
> public launch, so Wave-3 is executable from ONE page weeks from now instead
> of being reconstructed from memory. Each row LINKS to the runbook/ADR that
> owns the detail — nothing is duplicated here.
>
> **Wave structure (agreed 2026-07-03):** Wave 1 = deployment close-out
> (done — this doc is its last artifact). Wave 2 = CI unlock (GHE EMU
> migration lands). Wave 3 = pre-launch window (~1-2 weeks out), then the
> repo-only website phase runs in between. Feature-driven AWS work (M6 auth,
> M7 subscriptions) arrives as its OWN scoped batches — it is feature work,
> not deployment work, but keeps the same batch discipline.

## Standing coupling notes (not gates — things that bite renames)

- The wrapper AND deploy.yml recover the distribution id from the
  `quilty-web-dev-cloudfront-5xx` alarm's dimensions — renaming the durable
  stage or that alarm breaks both SEO/smoke gates.
- The ISR revalidation DLQ transform matches OpenNext's INTERNAL queue name
  (`QuiltyWebRevalidationEvents`) — re-verify after any SST/OpenNext bump
  (T2-14 runbook note).
- The canary zip path embeds `filemd5(apex.js)` — hashing only that file; a
  second canary script file would need the hash extended or it ships stale.
